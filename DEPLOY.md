## Step 3 - Set up GoDaddy FTP credentials as GitHub Secrets

This site is static output (no PHP/database), so the simplest reliable path is: GitHub Actions builds it, then FTPs the compiled `dist/` folder straight into `public_html` - no Node needed on the GoDaddy server at all. This sidesteps the cPanel Git-clone problems from the scorecan.com project (shared hosting often can't run `npm install`/build itself).

1. In GoDaddy cPanel -> FTP Accounts, create (or find) an FTP user scoped to the document root for tinkeringtech.com (usually `public_html` or `public_html/tinkeringtech.com` if it's an addon domain).
2. In your GitHub repo -> Settings -> Secrets and variables -> Actions, add:
   - `FTP_SERVER` - usually `ftp.tinkeringtech.com` or the server hostname cPanel shows on the FTP Accounts page.
   - `FTP_USERNAME`
   - `FTP_PASSWORD`
   - `FTP_SERVER_DIR` - the path FTP lands in, typically `/public_html/` (confirm in cPanel; trailing slash matters for the action).
3. Push to `main` (or re-run the workflow manually from the Actions tab). GitHub Actions will build and FTP the site over.

## Step 4 - DNS cutover from SiteGround to GoDaddy

Do this only after Step 3 has successfully deployed and you've checked the live GoDaddy hosting URL (cPanel gives you a temporary IP-based or subdomain URL to preview before pointing the real domain).

1. Check email first. If tinkeringtech.com currently has mailboxes on SiteGround, note the MX records before touching anything (SiteGround -> Email -> look up MX, or `dig MX tinkeringtech.com`). If GoDaddy will also handle mail, set up mailboxes there first and copy MX records over in the same change. If you want zero email downtime, keep MX pointed at SiteGround (or a third-party mail provider) even after moving web hosting to GoDaddy - MX and A/CNAME records can point to different providers.
2. In GoDaddy -> My Products -> DNS, either:
   - Point the domain's A record to GoDaddy's hosting IP (keeps SiteGround as registrar, only moves where the site resolves), or
   - Change nameservers to GoDaddy's if GoDaddy is now the full DNS host.
3. DNS propagation can take anywhere from a few minutes to 48 hours. Use `dig tinkeringtech.com` or whatsmydns.net to check propagation before considering it done.
4. Keep the SiteGround hosting account active for a few days after cutover as a rollback option, in case something's wrong with the new site.
